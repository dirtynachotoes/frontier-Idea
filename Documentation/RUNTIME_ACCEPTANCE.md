Do this only after the single complete native CI build succeeds and its consolidated candidate has been installed once. Do not install or runtime-test the earlier spatial DLL. 1. Use existing disposable TEST saves and known validated binaries. Preserve backups. Keep base Sunrise fly off for an obvious reversible result, and start near ground. Start Core with StartFrontier.cmd, start offline Sunrise/Destiny and NMS using the existing working launch/loader arrangements. Do not change loader/framework versions. Load an ordinary activity without the Frontier Lua controller. Leave NMS foreground; keep Sunrise running in the background rather than repeatedly switching for gameplay.
2. Press F8 once in NMS, walk and release movement keys. Expect host assist at the captured baseline × 1.25 after native acknowledgement. 3. Press F8 again: expect native override removed and NMS baseline restored. Repeat a few edges in this SAME session; holding F8 must not spam requests. Ordinary NMS actions may also generate existing legacy bridge pulses, so use a quiet local area. No new rewards/resources are expected.
4. Change to another ordinary Sunrise activity once as a batched developer check (not a gameplay handoff). No Frontier Lua controller is required. Context change must clear hover; a fresh F8 edge must re-arm only after real native readiness returns. This tests the new permanent dependency removal, not the old EDZ phase demonstration. The optional old phase display is backward compatible but not an acceptance prerequisite.

Baseline restore means the current user preference if base flight was already on. Keep this as the end of the SAME session; there is no request for a second game launch/reinstallation. Save ordinary TEST game state as usual, collect logs and quit both games.
